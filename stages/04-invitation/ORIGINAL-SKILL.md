# 动态婚礼电子请柬

## 执行约定

用普通语言与用户交流，由 Agent 管理配置与命令。沿用已有信息，只询问当前缺失且影响结果的内容。图片参考中的姓名、日期、照片不能替代用户资料。保留用户照片的人脸、衣着与真实构图。地图位置与爱情经历只使用用户提供或核实过的信息。所有姓名、日期、文案都保留为网页文字。

从当前技能目录定位 scripts/ 和 assets/，不要写死平台安装路径。Python 3.10+ 为基础运行条件。先运行 python3 scripts/doctor.py，根据输出及当前工具判断文件、图片、音频、网页预览和发布能力。缺少执行能力时，采集资料并交付配置与素材移交清单，明确生成及发布待执行。平台安装或导出时读取 references/platforms.md；不得代替平台真实测试声称已兼容。

## 制作流程

1. **采集。** 接收1至12张照片和新人称呼、宴会类型、公历日期、场地及地址，迎宾／仪式／开席分别采集，仪式或开席至少有一个。读取 references/intake.md 执行分组追问及场景措辞。不要求用户填写 JSON。
2. **选方向。** 看图能力可用时推荐封面并说明构图原因，由用户指定或沿用顺序。默认完整展示人物；铺满裁切须明确设置 fit 和 position。按 references/design.md 推荐现有三款，用户未指定时生成三款对比。
3. **建项目。** 按 assets/example.json 和 references/config.md 写 UTF-8 配置，执行 python3 scripts/project.py init --config <配置.json> --project <项目目录/project.json>。项目、原始素材、补丁、检查报告放在发布目录外。缺少资料时设 demo=true，字段留空，页面展示待确认项，勿编造真实内容。
4. **预览。** 执行 python3 scripts/build.py --config <project.json> --out <专用评审目录> --style all --preview-file <项目目录/preview.html>。三款共享资料，内嵌媒体预览可以离线使用、试听音乐、调节动效强度和粒子。预览调节仅用于比较，用户确定后同步至项目配置。
5. **检查。** 查看生成警告，检查照片主体、横竖图、长姓名和地址、手机窄屏、开帖／跳过／重播、音乐与静音、后台暂停及减少动画。按 references/validation.md 区分代码、浏览器、各 Agent、微信实机检查。无浏览器时保留待验证项。
6. **修改。** 先读取 project.json 或运行 status，依据自然语言生成仅含指定变更的补丁。执行 python3 scripts/project.py update --project <project.json> --patch <patch.json> --expected-revision <当前版本> --note <修改说明>，然后重建。嵌套栏目保留未改字段，照片列表为整组替换；重排照片时同步 cover_index。旧配置自动归一为版本2。错误输入不得覆盖上一版可用网页。续做与历史恢复读取 references/config.md。
7. **声音。** 默认风格对应的原创合成演示音乐，采用有声开启与静音入口，音量默认0.55。无音乐、曲目替换、截取及来源记录参照 references/music.md。需要 ffmpeg 的操作缺少工具时，提供可执行替代；不自动下载网络歌曲。动效默认 normal，系统减少动画优先。
8. **定稿。** 用户选定模板后写入 style，真实信息补齐后设 demo=false。执行 python3 scripts/build.py --config <project.json> --out <专用发布目录> --mode final，最终目录只保留 index.html、选定素材和不含源路径的构建摘要。明确演示网站使用 --allow-demo 并保留演示标记。不能将带待确认项的页面称为正式请柬。
9. **发布。** 按 references/publishing.md 使用用户选择且当前 Agent 可用的托管服务。先检查最终内容和公开范围，使用已有授权继续执行。发布整个最终目录，保持 media/ 相对结构。没有托管能力时交付可部署目录及明确步骤，勿声称产生公网链接。
10. **验证地址。** 获取真实地址后填写 public_url，重建绝对分享封面与可选二维码，再更新同一发布版本。运行 check_publish 检查实际页面和媒体字节，成功后 record-publication 记录当前发布状态。分享给好友时确认宾客无需登录；发布回执、匿名访问、用户微信实测分别记录，不能互相替代。
11. **选择分享方式。** 按 references/sharing.md 区分普通链接、二维码海报与微信标题卡片。通用网页标题和元数据不能保证微信卡片展示。无公众号和自有域名时推荐海报，用户已选择海报就直接执行；坚持标题卡片时再核实域名、账号权限、服务端签名和宿主能力，不要求所有用户先买域名或注册公众号。
12. **制作海报。** 读取当前项目，使用 python3 scripts/share_poster.py --config <project.json> --out <sharing/poster.png> --font <本地中文字体> --online-report <checks/online.json>。生成选定风格、完整封面、标题、姓名、婚期、场地、时间和真实链接二维码，记录 sharing.json。用户实测地址可用时以 --url-evidence 记录原话与日期；演示资料显式 --allow-demo，已知 AI 演示照片按 references/sharing.md 添加来源标记。缺少发布地址先发布，不制作虚构二维码；仅制作候选时显式标明链接待验证。
13. **检查与交付。** 检查海报文字、人物与手机缩略图，实际运行二维码解码并核对落地地址。微信长按识别、网页转发卡片、地图与声音均需实际域名上实机检查，代码不能代替。持久保存项目、海报和分享记录，交付访问链接、海报原图、保存后发给好友并长按识别的步骤、资料状态及实际完成／待完成项；不代发给联系人。
14. **续做。** 使用已有项目进行局部修改并更新同一站点。婚期、场地、模板、封面、文案或链接变化时重建海报，核对二维码并刷新分享记录；纯 BGM 或动效变化可保留海报图，核对落地页和记录已更新。

## 质量门槛

- 一张照片只承担封面展示，不重复填充相册。多图相册按比例布局，人物不被装饰遮挡。
- 原图保留；安装 Pillow 时发布副本矫正方向、压缩、清理元数据。缺少 Pillow 时如实报告未验证内容。
- 有声播放由明确点击触发，按钮反映实际播放状态；静音、重播入口和后台切换不意外出声。
- 动画支持跳过与强度调整；减少动画时静态阅读；脚本不运行时正文仍可阅读。
- 发布资料、安装 Skill、平台导出三类文件各有用途，项目配置与历史不得进入公开目录。
- 海报二维码采用本地真实编码，保留静区，不由图片生成模型绘制；程序解码通过与微信识别通过分开记录。演示海报保留标记，缺字或文案溢出不交付为成品。
- 执行能力与发布权限来自实际环境，Skill 不携带凭据、不绕过宿主权限，不把私人照片上传到用户未选择的服务。
